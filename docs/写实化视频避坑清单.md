# 写实化视频避坑清单（必读）

> ## ⛔ 硬性规定（2026-11-27 严重失误后制定，见踩坑记录第 58 条）
> 1. **视频阶段只许用「白模控制视频（深度/姿态）驱动」的最新模型。** 禁止纯图生视频、锚点首尾帧拼接（11-26 版全片因此动作飘忽、字幕和说话对不上，整片作废重做）。cloud/video_run.py 遇到没有控制视频的工作流会直接拒绝运行。
> 2. **开工前必须查当时最新的开源模型并试跑对比，不许沿用上次的旧模型或镜像自带的旧工作流。**
> 3. **先试 3 个代表镜头（多人运镜、两人互动、说话特写），新旧并排给用户确认后，再报全片花费、征得同意再开跑。**
> 4. **审查必须完整播放看动态和口型，不能只看截图。**
> 用「Blender 白模 → 云端 AI 写实化（二转三关键帧 + 换脸 + 图生视频）→ 本地合成」做短剧时，**每一条都是真实返工换来的教训**。
> 开工前通读一遍；每个阶段结束前按对应小节逐条打勾。细节和来龙去脉见 [踩坑记录.md](踩坑记录.md) 第九～十一节。

## 一、搭场景（白模）

- [ ] **镜头可能拍到的每一面墙都要有符合场景身份的陈设**（图书馆、食堂、教室三场都因为墙面空白整场重做过）：图书馆要有满墙书架、桌上台灯，宿舍要有床铺衣物，等等。墙面空着，二转三就画成空房间，视频模型又按提示词自己补陈设，同一场戏的镜头之间背景来回跳（图书馆整场重做，2026-11-25）。
- [ ] 公共场所要摆几个外形各异的背景人物，否则视频会照着主角复制出长得像他的路人。
- [ ] 固定家具（床、书架、书桌、衣柜、梯子、栏杆）永远不能为了让机位而被挪走或隐藏。
- [ ] 机位不能在墙外，现实里三脚架或手持的高度不超过 2.4 米。
- [ ] 桌子靠墙时，机位不能从墙那一侧拍。
- [ ] **墙上、台面上的固定设施**（打饭台、冷柜、宣传画、横幅、镜子、通知）都要列进 FIXED，否则机位会把它们当活动家具移走，某些镜头里设施凭空消失。
- [ ] 同一个道具只能有一份：布景里摆的道具和剧情里切换显示的道具不能重复（林晓手里拿着手机，床上还躺着一部）。
- [ ] 贴墙物件要离墙中线大于半个墙厚（墙厚 12cm），否则会埋进墙里。

## 二、人物动作和手握物体

- [ ] **人物库里的定妆描述、白模模型的服装、负面提示词三者必须一致**，服装还要符合作品基调（思政短剧不要用角色扮演式服装）。不一致时，视频里的衣服会在镜头间来回跳。

- [ ] **单手握手机是默认**，双手只在剧情需要时用。握法：四指一半贴在背面、一半包住侧边，拇指搭在屏幕上；屏幕朝向眼睛。
- [ ] **握住的物体必须贴合、不能穿模**。手机只有 8mm 厚，要单独检查（tests/hand_phone.py 的 INSIDE=0）。各角色手大小不同，要按手型自动校准（shoot.fit_held_phone），不能用一组固定偏移。
- [ ] 握栏杆、梯子、床架时，手要 IK 落到杆子上并握拳，不能悬在杆子旁边。
- [ ] 躺着看手机：手机举在脸的正上方（tests/lie_phone.py），不能伸到头顶后面。
- [ ] 薄道具（手机、书、纸）从机位看过去不能只剩一条边，否则会被画成棍子：躺着举手机时朝镜头一侧斜 35°。
- [ ] 挥手时手在头侧，不要整条胳膊举过头顶（那像举手提问）。
- [ ] 两人靠近（蹲下说悄悄话、拍肩）时，要按坐下吸附到椅子后的**真实位置**加上身体前倾量来摆，否则两人身体会嵌在一起。
- [ ] 动作不能僵：说话要带点头和上身起伏，站着要有重心转换，拿手机的手要有轻微晃动。

## 三、机位和镜头的第一帧

- [ ] **写实化只用每个镜头的第一帧当关键帧**，第一帧必须干净：不能被前景（自己的手臂、门框、床架）挡住，主体在画面里。
- [ ] 只换手臂姿势的手部或手机特写，手臂过渡要提前在上一个镜头末尾做完，特写一开场手就在位（s01_12 第一帧被小臂糊住）。
- [ ] 物件特写（通知、海报、手机、脚、桌面）要对准那个物件，不能对准人脸。对着人脸又不换脸，写实化会画出一个陌生人，甚至性别都不对。
- [ ] 人物近景不要从头顶往下拍。

## 四、写实化（云端）

- [ ] **纯图生视频会跑偏**：动作全由 AI 自己编，坐着会变站着，拍着拍着换了房间。11-25 试过的「锚点模式」（每 4 秒一张白模锚点、首尾帧控制）也救不回来，已弃用（cloud/_obsolete/make_anchors.py）。**视频一律用白模姿态/深度逐帧控制**（cloud/video_h3.py）。
- [ ] 只把镜头切细没用（段与段之间长相、光线会跳），必须相邻段共用锚点帧。
- [ ] 深色衣服的褶皱会被画成斑马纹，keyframes.flatten_dark 会自动处理。
- [ ] 看不到脸的镜头不换脸；看得到脸的必须换脸。
- [ ] 检查水印和凭空出现的文字。
- [ ] **关键帧一出来就逐张查人物的性别、发型、服装**是否和人物库一致：二转三曾把男主画成女生，母亲的发型前后不一，三人被画成黑西装。关键帧的提示词里要带性别和体型。
- [ ] 关键帧也要查人物：多人小景别里，衣服可能被二转三改掉（白衬衫变卫衣），几个人会长成一个样。关键帧错了，要连关键帧一起重做，只重跑视频没用。
- [ ] **不要用图片编辑工作流改人**（edit_ref.py / edit_photo.py 已弃用，在 cloud/_obsolete/）：双参考编辑会往画面里「加」一个人而不是替换。改人数、站位、衣着写 task 的 kf_hint 重做首帧；统一五官用本地 face_unify.py。
- [ ] 任务没做完时不要自己决定收工关机，先问用户。
- [ ] 首帧重做后先看图再生成视频：人数、谁在左谁在右、衣着、体型都要和白模锚点一致。
- [ ] 同一个镜头重跑三轮还是同一种错，就别再重跑：先查是首帧错（改 kf_hint 重做首帧）还是控制不够（调姿态/深度强度），再考虑改白模机位或剪辑绕开。
- [ ] 多人同框的镜头两人不要贴太近（同框越近越容易被画成同一个人），优先用过肩、背影、拉远。
- [ ] **内容底线**：思政短剧不能出现暴露服装、角色扮演服装。视频模型的文本编码器是 nsfw 版本，负面提示词必须带上这类词（looks.NEG_EN）；发光眼睛、凭空多出的人也写进负面提示词。

## 五、审查

- [ ] 合成前跑一遍 cloud/face_unify.py，逐帧把五官统一成人物库标准脸（inswapper 换脸 + GFPGAN 修复）。onnxruntime-gpu 的版本要和 CUDA 对上，并确认真的在用 GPU。（每批视频都要做，不要等成片）

判断标准：**符合剧情、符合现实物理规律**就保留，不要求和白模一模一样。重点是**镜头之间的衔接**。

- [ ] **状态前后一致**：鞋穿过就不能再穿一次，吃过的东西不能变回没吃，背包、衣服款式、眼镜不能时有时无。
- [ ] **空间连续**：现实时间里人不可能瞬移，比如上铺变下铺、洗手池变窗边、站着下一秒已经躺下。
- [ ] **动作重复**：已经下了床，下一个镜头不能又从梯子上落地。
- [ ] **人脸一致**：镜头里出现的每一张脸，包括手机屏幕里的、背景里的，都要和人物库的标准长相一致。开头不露脸、后面才露脸的镜头最容易冒出陌生的脸。
- [ ] **人体正常**：没有穿模、变形，没有正常人做不到的动作，人数和性别都对，同一个人不能变成另一个人。
- [ ] **光线、时间、背景一致**：同一场戏不能忽明忽暗、忽暖忽冷，背景陈设不能来回跳。夜戏中途不能变成白天，冷色调的回忆戏不能变成暖色阳光。
- 工具：
  - `cloud/continuity_review.py`：相邻镜头的衔接拼图；
  - `cloud/drift_review.py`：单个镜头的跑偏拼图。
- 有问题的镜头记进 `build/logs/drift_tasks.txt`，用锚点模式重跑。重跑上一个镜头，让它的结尾落回白模，就自然接上下一个镜头。

## 六、流程与成本

- [ ] **合成后核对总时长**：应等于各片段时间轴（最后一拍 f1）之和；短了说明有画面没进成片，配音字幕也会错位。
- [ ] 回忆戏、夜戏等统一色调放到后期调色（ffmpeg），不要指望 AI 每个镜头都画准。

- [ ] **云端显卡选 48G**（如 4090D 48G）：这条管线实测要占 33–42GB 显存，24G 卡一直报错出故障。抢不到 48G 宁可等。

- [ ] 规则改动后**只局部补拍必要的镜头**（设 `V11_RENDER_BEATS`），不要整段重拍、也不要把相关镜头全部重拍。
- [ ] 局部补拍不能清空其它帧，也不能按总帧数判失败（run_all.py 已处理）。
- [ ] 平台显卡空闲 30 分钟会自动关机：补跑要紧接着排上（用完成标记串起来，例如 `while [ ! -f DONE_xxx ]; do sleep 30; done` 后接下一批），不要等本地审查完才开始传。
- [ ] 本地监控日志不动，不代表云端停了，要用 ssh 直接查 kf/real 的数量。
- [ ] **下一阶段要排在云端，不要靠本地盯**：用 slim_pack.py 打包、传上去，在云端用「等上一批的完成标记 → 自动开始」的脚本排队（full_fun.ps1 / trial_h3.ps1 都是这样）。本地监控曾卡死，GPU 空等 40 分钟，差点被自动关机。
- [ ] 云端每个阶段的时限要够用：按镜头数 × 1.8 分钟（关键帧）、帧数 × 1.8 秒（视频）估算。时限太短会被强制截断，后面的镜头直接被跳过。
- [ ] 所有远程命令都要有硬超时；ssh/scp 要加心跳（ServerAliveInterval=15、ServerAliveCountMax=3），否则断网后会永远卡住（取回程序曾卡 4 小时）。
- [ ] 用 identity_check.py 给每批视频做长相初筛，被标记的再看截图确认（误报约一半）。目测合格的视频也要用它复查一遍。
- [ ] 改完脚本先检查语法、确认替换生效，再重启。
- [ ] **无人值守取回要有硬超时**：每条 ssh/scp 都加心跳（ServerAliveInterval）和 Start-Job/Wait-Job 硬超时；`full_fun.ps1 -Step pull`、`wait_fetch.ps1` 已内置，断了会重试。
- [ ] 不要用占显卡的程序躲避平台的空闲关机，要靠把真实任务排好来避免空闲。
- [ ] 改握法、改姿势后，先出特写图检查，再重拍；每次重拍和上云都很耗时，要一次把同类问题改全。
- [ ] 估时参考：关键帧约 106 秒/个，视频约 1.76 秒/帧（4090D），锚点段约 5 分钟/段。
- [ ] 新工作流先单张试跑、看图再批量：检查被静音的分组（mode 2）要不要 enable、写入的字段名在 API 里是否真的存在（写错不报错）；双参考编辑会「加人」而不是「换人」，换人用本地 face_unify。
- [ ] 提示词按镜头写：画面里几个人、谁在左谁在右、谁戴眼镜，要和白模锚点图一致（cloud/shot_prompts.py 覆盖）；关键帧就画错的改提示词，视频跑偏的才加密锚点。
- [ ] 开机先查「锚点关键帧比视频新」的镜头（上次欠费关机没跑完的），一起补跑。
- [ ] 两人挨得近的镜头关键帧不做 Qwen 换脸（noswap），交给本地按位置换；视频里冒出和主角相像的路人，用 bg_face 换成背景人物的脸，避免出现两个主角。
- [ ] 多人镜头关键帧不做 Qwen 换脸（会连衣服一起换、选错人）；提示词里的人物外貌和 looks.py 逐字核对（曾把周明远写成寸头）；成片前跑 cast_sheet.py 看每个角色全片是否一致。
- [ ] 提示词别写 eyes red / face clearly visible（会发红光、补脸）；白模里像球的半截身体在锚点图上抹掉；中间锚点画错就删掉只留首尾。
- [ ] 改角色外貌改 characters/<cid>/character.py 并重新生成、上传 looks_gen.json（looks.py 只是默认值）；关掉 Qwen 换脸后要核对体型（林晓会被画瘦）。
- [ ] 关键帧只读中文前缀：纠正关键帧里的人数/站位/体型写 task 的 kf_hint（shot_prompts.EXTRA），英文 prompt 只管视频阶段。
- [ ] 同一场戏的镜头并排核对衣着（同一天不能换衣服）；近景看不到帽子时提示词要写明是连帽卫衣。
- [ ] 说话镜头必须过 av_sync_check.py（嘴型与配音偏移 ≤2 帧、相关 ≥0.3、说话闭嘴 ≤40%）；旧版 49 个只有 2 个合格。
