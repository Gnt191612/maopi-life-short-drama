# 踩坑记录（v11，2026-11）

> 注：第 58 条以前提到的不少脚本（session.ps1、video_run.py、make_anchors.py、edit_ref.py、pull_done.ps1、watchdog.ps1 等）属于已弃用的图生视频做法，2026-11-27 起移到 `cloud/_obsolete/`，只作教训保留。现行做法见 [模型选型.md](模型选型.md)。


每条：**现象 → 原因 → 解决**（文件/参数）。做新短剧前先通读一遍，大部分坑都能提前绕开。

## 一、总体路线

| 现象 | 原因 | 解决 |
|---|---|---|
| v1–v10 用 AI 视频逐镜头生成：角色认不出、手机等道具变形、动作衔接断裂、口型对不上 | 视频模型每个镜头都在「重新想象」人物和道具 | 改为 **白模锁定一切（人物、位置、动作、道具、口型），AI 只负责最后的写实化** |
| 程序生成的人脸「大众脸」、不像想要的样子 | 只靠形态参数手调，没有目标 | **先定长相再建模**：每个角色用 AI 出几张写实候选，用户挑一张作标准长相（`assets/identity/<cid>.png`），白模照着照片拟合 |
| 白模的瑕疵（穿模、秃一块、裙腰露出）被写实化「画成真的」（裙腰 → 毛衣破洞） | 写实化模型把白模当真实结构 | 白模不必逼真但**不能有错**；每轮都出正/3/4/侧/背面对比图检查 |

## 二、人物：脸

| 现象 | 原因 | 解决 |
|---|---|---|
| 拟合「重新拟合」好几次都没生效 | 标注 JSON 里混进了 `skin_top` 这种非点数据，`photo_points` 解析报错被吞掉 | `face_fit_solve.py` 只收 `[x,y]` 单点；改完标注一定看拟合误差（`err_after`）有没有变 |
| 鼻子歪、鼻孔落到上唇 | 模型鼻翼取点范围跟着鼻底走，鼻底又能选到上唇；贴脸时把鼻翼点当「不一致点」剔除了 | 鼻翼区限制在鼻尖下 0.4 眼距内、排除唇部；`face_project.py` 永不剔除鼻翼/眼角点 |
| 胖的特征（脸颊肉、双下巴）拟合不出来 | 照片拟合只看正面轮廓，深度方向的特征拟合不到 | `build_cast.py` 的 `FIT_ADJUST[cid]` 手动补（满强度太胖，按一半起调） |
| 正脸嘴部突出 / 眼鼻之间一道褶 / 鼻梁直接弧线接眉骨 | MakeHuman 头模本身形状 | `FIT_ADJUST` 收嘴、`FIT_SMOOTH` 局部拉普拉斯磨平（保护睑缘 2~5mm）、垫山根 |
| 头顶尖、头顶到眉毛比例不对 | 头骨偏高 | `FIT_CROWN`（眼上 1 眼距以上按 k≈0.72~0.82 压低） |
| 嘴唇微张露出口腔暗色；用形态参数合拢会扯成方唇 | MakeHuman 默认嘴唇微张 | `LIP_SEAL` 几何封口；**新角色要加进 `LIP_SEAL`**，并删掉手调的 `LIP_TINT`（会盖掉照片唇色，嘴唇又肿又粉） |
| 贴脸后脸发灰/偏白、眉毛发灰 | 去光照过度；皮肤镜面反光叠在深色上 | `photo_tone` 眉毛带单独处理；烘焙后 Specular/Coat/Sheen 乘贴图亮度 |
| 贴图糊 | 烘焙时细分修改器开着 | 烘焙前关细分（`face_project.py` 已处理） |
| 眉尾被贴回模型皮肤 | 眉尾在太阳穴斜面上，「朝向」渐变把照片换掉了 | facing ramp 0.12~0.50 |
| 额头一道斜黑线（换一边又出现） | 照片发际线边缘的碎发被当成皮肤贴上去 | 照片 `skin_top` 标在真实头发边缘以内；额头过渡带加宽到 130px；`photo_masked` 自动去碎发（眉毛用平滑权重保护，硬边界会切坏眉毛） |
| 改了投影代码，旧瑕疵还在 | `face_project.py` 是叠在模型当前皮肤上烘焙的 | **改投影必须先 `build_cast` 重建再投**（`round2` 流程） |

## 三、人物：头发

| 现象 | 原因 | 解决 |
|---|---|---|
| 程序发丝做不出干净轮廓：头顶尖、刘海乱、两侧外张像耳机 | 发丝沿粗糙发片生长 | `blender/lib/hair_cards.py`：「主体厚壳 + 发片」，发际线按照片标注投影；**不要随机撒发片**（像鳞片） |
| 刘海帘、胎毛发片在素模里像梳齿/方块 | 发片浮在主体上 | 关掉 curtain，胎毛从发际线内 4~9mm 起越过发际线 |
| 侧面秃 / 头发盖住耳朵 | 整体抬高发际线让耳朵露出 | 头发包住耳周，只把耳朵本身附近 2cm 平滑沉到皮肤下 |
| 下颌/鬓角出现黑线 | 头发在发际线外只沉 1.5mm，身体渲染细分后凸面内收，头发透出来 | 男生发际线外沉 5mm；鬓角、下颌角不长头发 |
| 后脑勺像头盔/鲻鱼头，后颈一圈黑锯齿 | 后颈发际线太低；沉在皮肤下的发尾随姿势又顶出来 | 后颈发际线抬高；**发际线 1cm 以下的面直接删掉**，边缘挪到发际线上；头皮遮罩只限发际线内 5cm |
| 后颈透出一块块肉色 | 后颈是凹面，皮肤细分后往外鼓 | 后颈头发至少 3mm 厚 |
| 用户认可的发型在正式出片时变了 | 测试关了发丝（`V11_STRANDS=0`），正式出片会沿轮廓再长一层 | 用户认可的就是轮廓本身时，加进 `KEEP_SHELL` |

## 四、人物：身体与服装

| 现象 | 原因 | 解决 |
|---|---|---|
| 让别的会话改身材，被改废 | 多个会话同时改同一文件 | 一个人物只在一个会话里改；改坏用 git 回退 |
| 单项收得太狠导致比例失调（夸张沙漏、腿缝大、膝内扣） | 只盯局部 | 各项协调、适度；每轮看全身正/侧/背 + `V11_NOCLOTH=1` 只看身体 |
| 腿加长后脚沉到地下 | 腿长形态目标 | `ground_body`（绑骨前整体抬回地面） |
| 改身材后发际线投影错位 | 头的位置变了 | 发际线投影按两眼中心对齐（`lift = eyes.z − fit['eye_z']`） |
| 宽松衣服像麻袋/羽绒服、下摆露肚子 | 社区服装不合身 | `TOP_FIT`/`fit_cloth`、`shorten_top`、`push_out`、`hide_under`；没有合适素材就**从身体表面长衣服**（`lib/jk_sailor.py`：水手服、V 领上衣） |
| 从身体长出的上衣正面裤腰处总有一条缝 | 下摆不能低于裆部（两腿间没皮肤可长），而裤腰前面比裆部还低 | 下摆在裆部上方，再往下「续」一圈布（`ext`），罩在身体和裤子外 |
| 按颜色染衣服被原贴图压成灰 | 原贴图本身有颜色 | `jk_retex`：保留贴图明暗、整体换色 |
| 饰品飘到头顶 | 用了原始网格坐标，身材形态键已移动了耳朵 | 取**变形后**网格坐标（关掉遮罩/细分后 `to_mesh`） |

## 六、云端写实化（仙宫云 + ComfyUI 镜像）

| 现象 | 原因 | 解决 |
|---|---|---|
| 浏览器打不开 ComfyUI 新窗口 | 平台限制 | SSH + `cloud/comfy_run.py`（界面工作流自动转 API 格式） |
| 二转三画出第二个人、镜头拉远 | 预览帧只有 640×360，放大后很糊；又加了人物描述，模型从头重画 | **高清首帧**（`render_first.py` 1920×1080）+ **图生图从第 3 步起采样** + 不加人物描述 |
| 换脸把参考照片的长发、毛衣一起搬过来 | 整人替换模型 | 参考图**只裁脸**（`canonface_<cid>.jpg`），指令写「只换脸」 |
| 外景树仍是卡通、手机特写被贴了一张脸 | 重绘力度统一；所有镜头都换脸 | `keyframes.py` 的 `plan()`：无人镜头从第 1 步起重绘；看不到脸的镜头不换脸 |
| **视频全成了慢动作、只用了每段开头 1/4** | Wan2.2 Remix 工作流把 81 帧插到 321 帧存成 GIF，GIF 记的帧率是 8.3fps（错的） | 按「实际帧数 ÷ 应有时长」重算时间轴（`video_run.py`；本地 GIF 同理：`setpts=N/(320/5)/TB`） |
| 续接段截不到最后一帧 | GIF 用 `-sseof` 截不到 | 逐帧覆盖写 `-update 1` |
| 片头角色糊 | 832×480 横屏里角色只有 413px 高，片头放大到 885px | **竖屏 720×1280 生成**（首帧 = 原立绘） |
| 角色动作要后期叠到背景上 | 背景一起生成就改不了 | **绿幕生成**再抠像（`intro_compose.py` 的 `key_green`） |
| Krea2 编辑去掉照片里的行人：整张图被重画、还多出人 | 编辑模型对「移除」不可靠 | 本地修补（`cv2.inpaint` + 轻微颗粒），让角色站位挡住修补区 |
| `pkill -f video_run.py` 把自己的 SSH 会话杀了 | 匹配到了执行它的 shell 命令行 | 写成 `pkill -f '[v]ideo_run.py'` |
| 远程命令里的引号、JSON 层层转义出错 | PowerShell → ssh → bash → python 多层引号 | 小功能写成脚本文件上传后执行（`qctl.py`、`exp_real.py`） |
| PowerShell 函数 `R` 不能用 | 和内置别名 `r`（Invoke-History）冲突 | 函数名避开单字母（`Rx`） |
| 开机要 10~15 分钟 | 镜像自带 1TB 只读模型链接（删不掉） | 本地把所有不需要显卡的事做完再开机；能合并的任务合并到一次开机 |
| 两台实例空跑把余额耗光 | 跑完没关 | **一个阶段跑完、下一步不是马上要跑就立刻关机**；`session.ps1 -MaxHours` 预算保护；平台全局「GPU 闲置 30 分钟关机」兜底 |

## 七、配音与片头

| 现象 | 原因 | 解决 |
|---|---|---|
| CosyVoice2 配音难听又单调 | — | Spark-TTS 设计全新音色（不克隆真人）+ IndexTTS2 按「语气说明」逐句控情绪 |
| 8GB 显卡配音 RTF 17 | 情绪模型、whisper 和 IndexTTS2 同驻显存 | 先算情绪向量再卸载；whisper 放 CPU |
| 某个音色候选 59 秒（正常 8~10 秒） | Spark-TTS 偶发不停止 | 候选时长异常的直接作废 |
| 想要某音色但语速快 | — | `ffmpeg atempo` 放慢（0.85~0.9 音高不变） |

## 八、Windows / PowerShell / Git

| 现象 | 原因 | 解决 |
|---|---|---|
| JSON 读不了 | `Set-Content -Encoding utf8` 写入 BOM | `[IO.File]::WriteAllText(..., New-Object Text.UTF8Encoding $false)` 或用 Python 写 |
| 标注文件被清空 | Python 一行里先 `open(p,'w')` 再读同一文件 | 先读完再写 |
| `Edit` 改不上 / 改动丢失 | 文件被脚本改过，编辑工具要求重新读 | 每次脚本改完文件后先重新读再编辑 |
| `.ps1` 里中文乱码、解析失败 | Windows PowerShell 5.1 读无 BOM 的 UTF-8 当 ANSI | `.ps1` 存成 **带 BOM 的 UTF-8** |
| 一行 `python -c` 里多行代码出错 | PowerShell 对引号、`` `n `` 的处理 | 超过两行就写成 `.py` 文件 |
| 推送超时 | 网络 | 设 `HTTPS_PROXY` 后重试 |
| 本机上行很慢（约 0.35MB/s） | 家用宽带 | 大文件让云端自己从网上下载；上传包只放必需的（参考图存 JPG） |

## 九、白模拍摄：机位与姿态（2026-11-22 全片检查）

改了拍摄逻辑先用 `blender\tests\shot_review.ps1 <片段,...>` 快速审片：只搭建、每个镜头渲两帧、拼成 `build\review\<片段>.jpg`，几分钟看完一个片段，不用等整片渲染。日志里 `CAM FALLBACK` 会带上每个候选不合格的原因。

| 现象 | 原因 | 解决 |
|---|---|---|
| 林晓的头被拉长 10 倍 | `aim()` 写整个骨骼矩阵，缩放误差反复累积 | 每次写完 `pb.scale = (1,1,1)`；`reset()`、根骨骼也一样 |
| 人坐到桌面上、跪在桌上 | 落座射线先碰到伸过来的桌面边 | `support_height(kind='seat')` 跳过 table/desk/shelf 等 |
| 人陷进床里（被子盖到腰） | 被子底面和床垫面重合，射线穿过被子后起点在床垫里面，漏掉床垫面，人被压到床板上 | 软物件（被子、枕头）比支撑面高 5mm；被子 4cm 薄 |
| 拆掉的墙后面露出 HDRI 远山 | 室内也用了室外全景当背景 | 室内用 Light Path「Is Camera Ray」混一张纯色背景（光照仍来自 HDRI） |
| 路人 A-pose 站在原点 | 先加载人物、后判断要不要跳过 | 先判断再 `append_cast` |
| 开场空镜被大树挡掉半个画面 | 空镜机位不避让 | `clear_est_view`：画面里 9×5 条视线，15m 内挡住的树/路灯本拍隐藏 |
| 书架挡脸、书悬在半空 | 只拆了书架方块，书是嵌在里面的独立物体 | `with_resting`：连同放在上面、嵌在里面的东西一起拆 |
| 宿舍里大半机位「没有候选通过检查」 | 可移走的家具挡脸也直接判不合格 | 验证时把挡视线的可移走家具记下来本拍移走（`_HIDE_ACC`）；有人躺/坐的床整套不动 |
| 梯子横杆挡在脸前却判通过 | 只打一条视线，从横杆缝里穿过去 | 脸部打 4 条线（中、左、右、上） |
| 半个画面是墙、门框 | 只检查脸那一条线 | `_foreground`：画面 5×3 条视线，超过 1/3 被不可移走的东西挡住就换机位；窗玻璃、窗帘、门算活动墙 |
| 拍躺着的人只能从床垫底下拍 | 脸朝上时候选固定往 +X 转，床靠墙那侧 | 往房间中间那侧转，瞄准偏移沿身体方向 |
| 检查躺着的人总说被枕头挡 | 瞄的是头骨根部（后颈），埋在枕头里 | 瞄脸面（头中心 + 朝向 × 9cm） |
| 转身、起身、抬手的镜头都判不合格 | 要求三帧全部满足 | 三帧里「在画面里」「脸朝镜头」允许一帧不满足；会加跟拍的人不查出画；机位朝向按头的真实朝向（三帧平均） |
| 枕边手机特写只拍到一团头发 | 手机放在枕头方块里面了 | 手机放枕边床垫上；物件特写不对准人头（`object_target`），超近景退成近景 |
| 手机屏幕字缺笔画、像乱码 | Blender 文字曲线填不对 Noto Sans SC 的重叠轮廓 | 系统 Python + PIL 把文字画成透明 PNG 贴上去（`tools_text_png.py`），手动按宽度换行 |
| 屏幕字只显示一角 | 文字面片是立方体，自带 UV 每个面只占贴图一小块 | 贴图用 Generated 坐标 |
| 结尾跟拍画面歪 | DAMPED_TRACK 不管画面水平 | 跟拍用 TRACK_TO + `up_axis='UP_Y'` |
| 人坐在半空、脚陷进地板 | 剧本让人坐在没有椅子的地方，或站位偏离椅子 30cm | 要坐椅子却身下没座位：45cm 内有椅子就对过去，没有就放一张方凳（`make_stool`） |
| 人浮在椅子上方、大腿搁在桌面上 | 落座时把腿上方/下方的书桌当成支撑面 | 坐着时桌子不算支撑；高出身体点 15cm 以上的面不算 |
| 挥手时整个人被抬高 26cm | 垂下的手落在椅面边上，被当成臀部找支撑 | 落座只看躯干和腿（排除前臂和手） |
| 站起来的人像站在椅子上 | 起身后原地站着，椅子穿过腿 | 站立时脚下有椅子就往前迈 40cm |
| 黑色显示器挡住半个画面也不移走 | 显示器屏幕叫 `prop_screen_monitor_*`，和手机屏幕同前缀被放行（遮罩还被当成手机） | 改名 `prop_monitorscreen_*`；`prop_screen_*` 只给手机用 |
| 手部特写拍到一大块衣服 | 物件特写的视线检查忽略了本人身体 | 手附近 14cm 内的身体不算挡，胳膊、身子挡在前面算 |
| 没有合格机位时退回的镜头卡在人身体里 | 退回评分最高的候选 | 退回「问题最轻」的候选：出画 < 被挡 < 镜头在人身体里；同侧都不行时允许越轴 |
| 镜头第一帧卡在头发里 | 检查从第 3 帧开始 | 检查帧改成第一帧、中间、最后一帧 |
| 三人挤在一起的镜头卡在中间那人身体里 | 瞄准点（几颗头的平均再往下挪）落在中间那人胸口里，探路射线一出发就撞上她 | 探路时穿过被摄主体自己的身体（own_rigs）；镜头离任何人身体 30cm 内算前景遮挡 |
| 审片图和上一轮一模一样 | 搭建报错退出了，审片渲染打开的是旧 .blend | shot_review.ps1 搭建失败就报 BUILD FAILED 并跳过；用脚本改代码后先 st.parse 检查，注释别插进一行中间（会把后半行注释掉） |
| 台词听着赶 | 个别长句接近 6 字/秒（中位 4.5） | `voice_tools/pace_lines.py`：超过 5.6 字/秒的句子 atempo 放慢（最多 0.85 倍），原音备份 `assets/audio/_orig/`，删口型 json 让 run_all 重新生成；急的句子（催起床）保留 |

## 十一、手握物体（手机、栏杆）的写实规则（2026-11-24 用户逐条指出）

1. **单手握手机是默认**：现实里单手看手机最常见，`phone` / `phone2` 都是单手（phone2 只是拿低一点，避免挡脸）。需要双手时在 ARMS 里加 `support=True`，左手才会托到右手后面并握拳；左手不托东西时不握（`grips()` 按 `support` 判断）。
2. **握法的形状**：以四指为界，一半在手机背面、一半包住侧边，**拇指搭在屏幕正面**；双手时两只手在背面一前一后叠着。手机竖着，长边沿食指→小指方向，屏幕朝眼睛（`orient_phone_hand`，SCREENDOT≈0.99）。
3. **背面四指要贴合、不能穿模**。手机只有 8mm 厚，通用的 1.5cm 穿模阈值永远查不出来，要单独数「落在手机盒子里的手部顶点」（clip_check 的「手机穿手」、`tests/hand_phone.py` 的 INSIDE 行）。
4. **不能用一组固定偏移**：各角色手的大小不一样，同一组参数下陈瑶 5 个点、林晓 46 个点插进手机。现在 `shoot.fit_held_phone` 按每个角色的手型自动校准：
   - 沿屏幕法线推/拉手机，让背面刚好贴住四指（留 0.6mm）；
   - 指尖还插进手机的，那根手指的末两节每次少弯 4°，直到不穿模（`rig['grip_ovr']`）；
   - 拇指三轴网格搜索：不穿模、指肚离屏幕约 1mm、伸进屏幕约 1.5cm（`rig['thumb_rot']`）。只绕 X 轴弯拇指只会让它翘在手机外面，必须三轴转。
   - 结果缓存在 `build/cache/grip_<cid>.json`，握法参数、手机尺寸、网格变了会自动重算。
5. **量手型时只看骨骼权重组**：MPFB 身体网格上还有 `Left`/`Right` 这类整侧标记组，权重全是 1，取最大权重组会全部变成 `Right`。另外评估后的网格（遮罩修改器删了辅助几何）顶点数和原网格不同，顶点组要从 `to_mesh()` 的结果里取，不能用 `body.data.vertices`。
6. **手机机身是缩放过的单位立方体**：bound_box 是 ±0.5，算穿深要乘 scale，不然会得出 400 多 mm 的"穿深"。
7. **腕骨局部轴（实测，右手）**：+Y 指向手指，−X 是掌心朝向（手指往 −X 弯），+Z 是食指/拇指一侧；骨骼父级子物体的原点在骨头**尾端**（腕骨长约 3.9cm），位置要减骨长。
8. **握栏杆、梯子、床架**：手要真的 IK 落到杆子上并握拳（`climb_low` 的 rails 做法），不能悬在杆子旁边。
9. **检查流程**：改握法后先跑 `tests/hand_phone.py <cid> phone`，看 INSIDE=0、三个方向的特写图，再给用户看图确认，然后才重拍片段（每次重拍和上云都很耗时）。
10. **局部补拍，不整段重拍**：规则改动后只补「问题在画面里看得清」的镜头（手部/打字特写、用户点名的），远景、屏幕特写不补。设 `V11_RENDER_BEATS=拍id,...`：`shoot_segment.py` 整段动画照样搭（保证时间轴、机位一致），但只渲涉及这些拍的镜头帧；`pack_for_cloud.py --update` 只重打这些镜头，其它镜头的旧任务和旧帧保留；云端也只重跑这几个任务。补拍前别删整段的 renders_preview。
11. **云端运行中热替换素材，不必单独补一轮**：云端解压后的素材在 `/root/v11cloud/cloud_pack/<任务id>/`，`keyframes.py` 和 `video_run.py` 按 manifest 顺序处理，轮到哪个镜头才去读它的 first.png 和 beauty/depth/pose。所以本地补拍完以后，把这几个任务目录直接覆盖上去：还没轮到的镜头就会用新白模生成，零额外开机时间。已经做过关键帧的镜头要删掉 `kf/<id>.png` 和 `real/<id>`，等全片跑完后用 `-Only` 补一小轮。前提是补拍后切镜帧位不变，任务 id 才会一致。
12. **本地监控日志不动，不代表云端停了**：`session.ps1` 只在云端日志有变化时才打印，ssh 轮询偶尔也会卡住。判断进度要直接 ssh 查 `ls kf | wc -l`、`stat -c %Y kf/*.png`（算每个镜头的耗时）、`nvidia-smi`。注意云端时钟和本地不在同一时区。
13. **估算完成时间的方法**：关键帧约 106 秒/个（4090D，含换脸）；Wan2.2 图生视频约 1.76 秒/帧，全片 14623 帧约 7 小时；本地搭一段动画 1~10 分钟（s10_00 最慢，约 10 分钟），预览渲染约 1.2 秒/帧。
14. **云端命令别塞进 PowerShell 双引号**：`ssh ... "python3 -c \"...open('x')...\""` 会被 PowerShell 拆开（把 `open` 当成命令执行）。云端命令要放进单引号变量 `$cmd='...'` 再传给 ssh，里面避免再嵌一层 awk 的 `$`。
15. **写实关键帧要回头查白模**（11-24 夜，全片关键帧出来后逐张看）：

16. **纯图生视频会跑偏，用锚点（首尾帧）模式拉回来**（2026-11-25）：
    - 现象：现在的云端视频工作流（Wan2.2 Remix i2v）只用白模的第一帧，后面的动作全是 AI 自己编。全片抽查的前 29 个镜头里有 11 个跑偏：坐在上铺的人站到了地上、拍着拍着换了个房间、脚的特写变成了脸的特写。
    - 方案（不用下载新模型）：
      - 本地 `cloud/make_anchors.py` 给镜头每 96 帧（4 秒，换算到 16fps 正好是 4k 帧）取一帧白模，再加最后一帧，按原机位渲 1080p，生成 anchor_####.png 和 anchors.json；
      - 云端 `keyframes.py` 给每个锚点出一张写实图 kf/<id>@####.png；
      - `video_run.py` 用相邻两个锚点做首尾帧控制：把 WanImageToVideo 换成 WanFirstLastFrameToVideo，用的还是原来的 Wan2.2 i2v 模型。
    - 实测（s05_01_0411）：视频最后一帧和锚点写实图基本一致，长相前后统一，1 段约 5 分钟。
    - 为什么不能只把镜头切细：每段各自从白模首帧重新生成，段与段之间长相、光线会跳。锚点模式里相邻段共用同一张锚点图，所以能接上。
    - 怎么判断跑偏：`cloud/drift_review.py` 拼图，每个镜头一行 = 白模首帧、白模末帧、写实首帧、写实中间帧、写实末帧。人工看完，把跑偏的镜头 id 记进 `build/logs/drift_tasks.txt`，`post_chain.ps1` 会在全片结束后用锚点模式重跑它们。
17. **ssh 远程命令带引号就写成脚本文件**：PowerShell 调用 ssh 时会吃掉命令里的双引号，`python3 -c "..."`、`sh -c '...'` 都会坏。先把命令写进 .sh 文件，scp 上去，再用 `bash 文件` 执行。
18. **跑偏的判断标准（用户 11-25 定）**：不要求和白模完全一致，符合剧情、符合现实物理规律就保留。只有这几类才重跑：人体穿模或变形、多出或少了人、人物性别或长相不对、水印和文字、动作违反剧情、凭空出现或消失的道具。锚点模式留作备用。

## 十二、严重失误：2026-11-27 全片写实化视频不合格（必须吸取）

58. **【严重失误】11-26～27 这一版成片整体效果很差，动作飘忽，字幕和人物说话、动作对不上，用户判定不合格，全片视频要重做。** 前后开了多次机（最后一次约 6 小时、14 轮补拍，约 ¥17），钱花在给一个用错了的方法打补丁上。
    - **根本原因（方法选错，不是参数没调好）：** 视频阶段用的是社区镜像自带的「Wan2.2 Remix i2v 3.0 自动反推+图生视频」，**没有用白模动作视频做控制**（video_map.json 里 control_video 为 null）。只给模型几张锚点图（每 2～4 秒一张，首尾帧控制），中间的动作全由模型自己编：
      1. 人物乱动，镜头自己推拉漂移，走位不按白模；
      2. 锚点图一张张独立生成，脸、衣服、光线、背景各有差别，视频在它们之间硬过渡，画面像在流动；
      3. 每 2～4 秒拼一段，运动方向和速度接不上，一顿一顿；
      4. 工作流的「自动反推提示词」冲淡我们写的动作描述；
      5. 白模里按配音做好的口型和按台词排好的动作节拍全部丢失，说话时嘴是闭的，字幕和动作对不上；
      6. 本地逐帧换脸没有前后帧平滑，脸轻微抖动；
      7. 16fps、832×480 生成，再插帧、放大到 1080p，动作发软。
    - **为什么拖了这么久才发现：** 每次只盯着一个个镜头的具体错误（多出人、换衣服、变瘦）逐个补，没有退一步审查「整段动作看起来自不自然、和台词对不对得上」。11-19 最初设计的 VACE 动作控制方案，是因为当时 24G 显卡一直报错才退而求其次改成图生视频，之后换到 48G 显卡时**没有回头重新评估**，一直沿用退而求其次的方案。
    - **今后的硬性规定：**
      1. **视频阶段只许用「白模控制视频（深度/姿态）驱动」的模型**，禁止再用纯图生视频、锚点首尾帧拼接的做法。video_run.py 已加检查：control_video 为空时直接拒绝运行。
      2. **开工前必须查当时最新的开源模型**（看 ComfyUI 官方文档、模型发布日期、实测对比），不许沿用上一次的旧模型。社区镜像自带的工作流不等于最好，镜像标题里的模型名不代表适合我们的任务。
      3. **先小规模试跑**：挑 3 个有代表性的镜头（多人运镜、两人互动、说话特写），新旧并排给用户看，确认明显变好后再算全片花费、征得同意再全片跑。
      4. **审查要看动态，不能只看截图**：每批结果至少完整播放几个镜头，看动作是否自然、口型和字幕是否对得上；用 cloud/dialog_audit.py 核对每句台词时的画面。
      5. 硬件条件变了（显卡换大、模型更新），要回头重新评估之前因条件限制被放弃的更好方案。
59. **音画不同步的量化结论**（11-27 用户指出旧版角色语音和动作、口型对不上；cloud/av_sync_check.py 实测）：
    - **声音本身的时间是对的**：每个镜头的配音轨和成片音轨互相关偏移 0～10 毫秒，问题全在画面。
    - **旧版 49 个单人说话镜头只有 2 个合格**（标准：嘴型和声音偏移 ≤2 帧、相关 ≥0.3、说话时闭嘴帧 ≤40%）；多数「说话不张嘴」占 40%～100%，偏移常到 ±8 帧。
    - **白模本身的口型也很弱**（8 个抽查只有 1 个合格）：说话镜头大多低头、嘴部动作幅度小，图生视频又没有跟白模走，等于完全没有口型。
    - **对策**：新方案说话镜头一律用 LatentSync 按真实配音重画嘴型；成片前用 av_sync_check.py 验收，不合格的不进成片。多人同框的 8 个说话镜头 LatentSync 只改最大的脸，需要按白模头部位置裁出说话人再对口型（待做）。说话特写尽量让白模抬头、正脸或半侧脸，低头和背影的说话镜头口型修不了。
60. **以前几版失败的根源和 11-26 版相同：做法错，不是模型差**（11-27 查历史记录）：第一版（11-10）用的是排行榜第 2 的商业模型 Seedance 2.5（ClawHive 接口，积分用尽后 403），v5～v9（11-11～12）用阿里云百炼通义万相（wan2.5-i2v-preview 为主，另有 wan2.2-i2v-flash/plus、wanx2.1-i2v、wan2.6/2.7-i2v、wan2.2-s2v），用户评价都是「逻辑极差、反复慢放、像动态幻灯片」；MiniMax 视频模型当时从未用过（ClawHive 资产列表里有但调用不了，aihub 模型表里的 MiniMax 是 M2.5/M3 等语言模型）。**每个镜头凭一张图或一段文字单独生成、镜头之间没有连续的动作和场景约束，模型再强也救不回来。** 所以 11-27 起的方案是 MiniMax H3（当前开放权重第一）+ 白模姿态/深度逐帧控制，关键在控制而不只是换模型。另：百炼不开「免费额度用完即停」开关时，免费额度用完后接口照常返回、悄悄扣费，阿里云欠费大概率由此而来——任何按量计费的接口都要先确认有硬性封顶。
61. **开机失败不一定是没卡：控制台显示「开机速度：异常」**（11-27 5:40～11:30）：连续 6 小时点开机都提示无卡（偶尔一闪而过的 48G 卡也开不起来），用户判断是实例本身「开机速度异常」导致无法开机（该实例系统盘已用 1.12 TB），已联系客服。**教训：控制台出现「开机速度异常」提示时先找客服处理，不要只靠抢卡；磁盘别堆中间产物（旧版视频、GIF、压缩包、废弃模型），跑完一轮就清理。** 自动抢卡脚本要写在页面里、状态存 window 变量，页面刷新后要重新启动（这次中途丢过一次）。
62. **【严重】旧实例开不了机，只能销毁重建**（11-27）：实例 4B5F 用了约两周，控制台提示「开机速度：异常」，从 5:40 到 11:30 连续约 6 小时开不了机，白白耽误一上午，最后销毁重建，云端上最新版的高清写实首帧（约 20 张本地没有、其余本地是旧版）随之丢失，要花约 3 小时、¥8～10 重做。
    - **真正的原因（11-27 新建实例时查明，更正最初的判断）**：① **关机保留磁盘的实例只能在原来那台物理机上开机**——同一时刻「部署新实例」页面 4090D 48G 可以选，旧实例的开机框里却一直「暂无可用」，因为它那台机器的卡全被别人占着；② 镜像本身就有 **1.08 TB**（系统盘 1.12 TB 里我们自己的中间产物只有约 40 GB），大镜像开机慢。最初以为是我们堆积导致，其实堆积只是次要因素。
    - **对策**：开不了机时直接**新建实例**（会分到别的机器），不要死等原机器；重要产物每轮同步回本地，才能随时销毁重建不丢东西。**不要为了开机快去换体积小的镜像**：选镜像以生成效果为第一优先（用户 11-27 明确要求），大镜像开机慢就提前开机、开机等待期间做本地准备。
    - **次要因素：我们的中间产物（约 40 GB）**：每轮补拍都把旧版视频挪进 `old_iv*` 而不是删除（14 轮下来十几个目录）、每段视频的预览 GIF、结果压缩包 `v11_result_*.tgz`、每轮上传的素材包 zip、ComfyUI 的 output/temp、下载后又弃用的模型；结果早已取回本地，云端却一直留着。
    - **为什么没早发现**：只在意 GPU 有没有空转，没有磁盘和「实例绑定哪台机器」的概念；控制台的「开机速度异常」提示出现后以为只是没抢到卡。
    - **改进（已落实到脚本）**：
      1. `cloud/disk_guard.sh`：每次开机后、每轮开跑前自动体检，剩余 < 80 GB 或已用 > 400 GB 就先自动清中间产物；清完仍不够就停下（DISK_LOW），把最大目录清单交给用户决定删哪些模型，绝不让磁盘继续涨。`trial_h3.ps1`、`full_fun.ps1` 的云端流程第一步就是它。
      2. `cloud/cleanup_auto.sh`：只删我们自己的中间产物和「已取回本地」的成品（取回脚本每取回一个文件就记进 `/root/v11_out/.pulled`），**写实首帧 kf/ 永远保留**，模型和镜像自带内容一律不碰。试跑取回后立即清；全片取回过程中每取回 10 个就清一次。
      3. 旧版视频不再「挪到 old_ 目录保留」：先取回本地，再在云端删除（本地已有备份就够了）。
      4. **重要的云端产物（写实首帧）每轮都同步回本地**，这样实例出问题时可以直接销毁重建，不丢东西。
      5. 控制台出现「开机速度异常」时先查磁盘、找客服，不要只靠抢卡。
      6. 一部片做完、确认不再需要时，导出要留的东西后销毁实例，不要长期关机保留（关机保留磁盘也按天收费）。
