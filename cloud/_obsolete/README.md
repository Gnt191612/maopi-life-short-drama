# 已弃用的做法（只作教训保留，不要再用）

2026-11-27 起，正片写实化改用 **MiniMax H3 + 白模姿态/深度逐帧控制 + LatentSync 对口型**，见 [docs/模型选型.md](../../docs/模型选型.md)。
这里的文件是之前的做法，结果被判定失败或已被替代。留着是为了让以后的人看到「哪些路走不通、为什么」，详细经过见 [docs/踩坑记录.md](../../docs/踩坑记录.md)。

| 文件 | 原来做什么 | 为什么弃用 |
|---|---|---|
| `video_run.py`、`video_map.json` | Wan2.2 Remix i2v 3.0 图生视频（写实首帧 + 锚点首尾帧） | **11-26 版全片因此不合格**：没有白模动作控制，动作飘忽、人物乱动、镜头自己漂、口型和配音对不上（49 个说话镜头只有 2 个合格）。踩坑记录第 58 条 |
| `make_anchors.py` | 锚点模式：每 2～4 秒渲一张白模锚点图做首尾帧控制 | 锚点图各自独立生成，彼此有差别，视频在它们之间硬过渡，画面像在流动；中间动作仍由模型自己编 |
| `session.ps1`、`session_realism.sh`、`cloud_queue.sh`、`run_multi.ps1`、`shard_pack.py`、`hot_swap.ps1` | 旧的一条命令写实化会话、云端排队、多机并行、热替换 | 视频阶段调用的是上面的图生视频；已被 `trial_h3.ps1`、`full_fun.ps1` 替代 |
| `pull_done.ps1`、`watchdog.ps1` | 旧流程的逐步取回、无人值守看门狗 | 和旧会话绑定；新流程 `full_fun.ps1 -Step pull`、`wait_fetch.ps1` 自带心跳、硬超时和重试 |
| `next_round.ps1`、`next_cloth.ps1` | 11-26 夜的补拍脚本 | 走旧视频流程；这些镜头在 H3 全片重做时一起重做 |
| `edit_ref.py`、`edit_photo.py`、`edit_probe.py`、`cloud_edit_queue.sh` | 用 Krea2 图片编辑工作流在关键帧上改人 | 双参考编辑会往画面里**加**一个人而不是替换；二转三工作流出左右拼接的对比图。改人用 kf_hint 重做首帧 + 本地 face_unify.py。踩坑记录第 39、40、48 条 |
| `realism.py`、`setup_cloud.sh` | 11-19 的 Wan2.1-VACE 方案 | 当时 24G 显卡一直报错，退而求其次改成图生视频（这个「退而求其次」后来一直没回头重新评估，是 11-26 失败的起点） |
| `exp_real.py`、`probe_comfy.py` | 早期二转三对照实验、旧镜像节点探查 | 实验已结束；新镜像探查用 `cloud/probe_h3.sh` |
| `写实化会话流程.md`、`README_仙宫云.md`、`cloud_render.md` | 旧流程说明 | 描述的是上面这些已弃用的做法 |

更早的版本（11-10 用 Seedance 2.5、11-11～12 用阿里云百炼通义万相）失败的根源相同：每个镜头凭一张图或一段文字单独生成，镜头之间没有连续的动作和场景约束（踩坑记录第 60 条）。
